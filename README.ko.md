# Window Holder

[English](README.md)

멀티 모니터 환경에서 맥이 절전모드(sleep)에 들어갔다가 깨어날 때,
디스플레이 신호가 잠깐 끊기면서 창들이 다른 모니터로 옮겨지거나
엉뚱한 위치에 놓이는 문제를 막기 위한 메뉴바 상주 앱입니다.

## 동작 원리

1. **디스플레이 배치 지문**: 연결된 모니터들의 시리얼/해상도/화면 좌표를 조합해
   "지금 이 조합의 모니터가 이 배치로 연결되어 있다"는 지문을 만듭니다.
2. **저장**: 1분마다, 그리고 절전 진입 직전(`willSleep`)에 Accessibility API로
   모든 앱 창의 위치/크기를 캡처해서 현재 지문에 매핑해 저장합니다
   (`~/Library/Application Support/WindowHolder/layouts.json`).
3. **복원**: 깨어날 때(`didWake` / `screensDidWake`) 새로 지문을 계산해서
   저장된 배치와 일치하면 각 창을 원래 위치/크기로 되돌립니다. 외부
   모니터가 재협상에 몇 초 걸리는 경우를 대비해, 화면 구성이 안정될 때까지
   기다렸다가(debounce, 최대 대기시간 있음) 복원하고, macOS가 다시 창을
   흐트러뜨릴 경우를 대비해 잠시 뒤 한 번 더 안전하게 재적용합니다.

## 설치

### Homebrew

```bash
brew tap owlhyxxn/window-holder https://github.com/owlhyxxn/window-holder
brew install window-holder
```

`brew install`이 끝나면 Spotlight/Launchpad에 뜨게 하려면 `~/Applications`로
복사하는 명령어를 안내해줍니다 (Homebrew 경로로의 심볼릭 링크는 Spotlight가
안정적으로 인덱싱하지 않아서, 실제 복사본이 필요합니다). 복사 없이 바로
실행만 하려면:

```bash
open $(brew --prefix)/opt/window-holder/WindowHolder.app
```

### 소스 빌드

```bash
./build.sh
open WindowHolder.app
```

메뉴바에 아이콘이 뜹니다 (Dock에는 표시되지 않음, `LSUIElement`).

### 첫 실행 시 필수: 손쉬운 사용 권한

다른 앱의 창 위치를 읽고 옮기려면 macOS의 **손쉬운 사용(Accessibility)** 권한이
필요합니다. 처음 실행하면 시스템이 권한 요청 다이얼로그를 띄우며, 메뉴바
아이콘을 클릭했을 때 권한이 없으면 "⚠️ 손쉬운 사용 권한이 필요합니다…" 항목이
보입니다. 클릭하면 시스템 설정의 해당 화면으로 이동합니다.

시스템 설정 > 개인정보 보호 및 보안 > 손쉬운 사용 > WindowHolder 체크

## 메뉴 항목

- **지금 배치 저장 / 지금 배치 복원**: 수동 트리거
- **자동 저장 (1분 간격)**: 끄면 절전 직전 저장만 동작
- **로그인 시 자동 실행**: `SMAppService`로 로그인 항목 등록/해제
- **언어**: 기본은 시스템 언어(`Locale.preferredLanguages`)를 따르고, 한국어
  또는 English를 직접 선택해서 고정할 수도 있습니다. 선택한 값은
  `UserDefaults`에 저장돼서 재시작해도 유지됩니다.
- 하단에 현재 디스플레이 구성과 저장 여부 표시

## 알아둘 점 / 한계

- 창 매칭은 1순위로 **창 제목**, 실패 시 2순위로 **원래 순서(index)**를
  사용합니다. 제목이 없는 창(일부 유틸리티 앱)이나 여러 개의 동일한 제목을
  가진 창(같은 문서를 여러 창으로 연 경우 등)은 완벽히 매칭되지 않을 수
  있습니다.
- Full Screen(전체 화면) 상태이거나 별도 Space(가상 데스크톱)에 있는 창은
  Accessibility API로 위치를 바꾸는 것이 macOS 특성상 제한적으로 동작합니다.
- 앱이 계속 실행 중이어야 동작합니다 (로그인 시 자동 실행 켜두는 것을 권장).
- 동일한 모니터 조합이라도 macOS가 disconnect/reconnect 시 시리얼 번호를
  못 읽는 저가/노브랜드 모니터의 경우 지문이 불안정할 수 있습니다. 이런
  경우는 vendor/model 값만으로도 어느 정도 안정적으로 잡히지만, 100% 보장은
  아닙니다.
- 저장된 배치를 적용하기 직전, 최소화된 창은 잠깐 펼쳤다가(그래야 프레임을
  실제로 지정할 수 있음) 다시 최소화합니다 — 복원 중에 창이 도크에서
  나왔다가 들어가는 게 보이는 이유입니다. 대부분의 앱이 최소화된 창의
  프레임 변경을 무시하기 때문에, 정확한 복원을 위해 현재는 이 과정이
  필요합니다.

## 업데이트 알림

앱이 실행되면 (그리고 이후 24시간마다)
[GitHub Releases](https://github.com/owlhyxxn/window-holder/releases)의
최신 태그를 조회해서 지금 빌드보다 새 버전이 있으면 메뉴바에
"🆕 새 버전 있음" 항목이 뜹니다. 클릭하면 릴리즈 페이지가 열릴 뿐, 자동
다운로드/설치는 하지 않습니다 (소스 빌드 배포 방식이라 각자 pull 후
재빌드해야 함).

새 버전을 낼 때는 아래 두 가지를 맞춰야 알림이 정상 동작합니다:
1. `Resources/Info.plist`의 `CFBundleShortVersionString`을 올리기 (예: `1.1.0`)
2. GitHub에 그 버전과 맞는 태그로 릴리즈 생성 (예: `v1.1.0`) — `v` 접두사는
   있어도 없어도 무방하게 파싱합니다.

## 코드 서명에 대해

`build.sh`는 ad-hoc 서명(`codesign --sign -`)을 사용합니다. 개인 로컬 사용
목적이면 충분하지만, 바이너리를 재빌드할 때마다 서명이 바뀌므로 macOS가
손쉬운 사용 권한을 다시 물어볼 수 있습니다. 매번 다시 허용하기 번거롭다면
Xcode에서 개인 개발자 인증서로 서명하는 것을 고려하세요 — 안정적인 서명
정체성을 쓰면 재빌드해도 권한이 유지됩니다.
